# 常见问题与故障排查 (FAQ & Troubleshooting)

本文档整理了使用 **EdgeTunnel Gateway** 过程中的常见问题与排查方法。

---

## 1. 客户端连接与协议

### Q1: 客户端配置为什么必须设置 `tls: false` (或 `security: none`)？
> **答**：客户端直连的是局域网内的网关设备（如 `10.10.10.35`），内网不存在公网 TLS 证书。真正的端到端 TLS 1.3 / HTTP/2 握手发生在**网关出站连接 Cloudflare 边缘服务器**时，由网关携带真实的 Worker/Pages 域名建立加密传输。若在客户端开启了 TLS，会导致局域网内握手报错（`certificate expired` 或 `self-signed certificate`）。

### Q2: 为什么 v2rayN 和 Mihomo 可以共用 8788 端口？
> **答**：Xray-core (v2rayN) 在 `security: none` 时使用明文 `HTTP/1.1 POST`，而 Mihomo 在 `tls: false` 时发送 RFC 7540 标准的明文 H2C 握手前言（`PRI * HTTP/2.0...`）。网关在 8788 端口通过首包字节嗅探，分别交由内置的 H2C 引擎或 HTTP/1.1 引擎处理，实现单端口无缝兼容。

## 2. 节点可用性与熔断机制

### Q3: 网关的熔断触发条件是什么？
> **答**：网关区分网络链路层异常与真实业务阻断：
> - **优选链路故障**：若客户端指定的优选 IP 出现丢包、TCP 超时（`ETIMEDOUT`）或连接拒绝（`ECONNREFUSED`），属于物理优选链路异常，不计入 Worker/Pages 业务失败；
> - **业务失败条件**：成功连接至 Cloudflare 边缘节点，但明确返回 `1101`（脚本异常）、`502`、`429`、`521` 等业务阻断状态码时，计入失败次数；
> - **熔断处理**：单节点连续遭遇 5 次业务阻断后，自动隔离熔断 60 秒，期间流量平滑切换至其余健康节点；隔离期满后重新加入可用池。

### Q4: 监控中心显示的节点成功率是否受优选 IP 影响？
> **答**：不受影响。物理网络传输层错误（超时、断开等）在第一道过滤层直接拦截，仅记录优选 IP 异常，节点卡片的转发成功率真实反映 Worker/Pages 后端本身的可用情况。

## 3. Cloudflare 额度与调度

### Q5: Cloudflare 额度达到多少会自动暂停使用？
> **答**：默认阈值为 **95%**。当某个后端关联绑定的 Cloudflare 子账户当日请求额度消耗达到该阈值时，网关动态调度时会自动将该节点移出健康池，优先调度其他未超限账户。若所有账户均达到阈值，网关会自动降级保留所有节点继续轮询，避免断网。该阈值可在控制台“核心配置”中调整（10% ~ 100%）。

### Q6: 为什么监控中心的额度数据会自动更新？
> **答**：网关后台运行着每 5 分钟周期的静默巡检任务，自动轮询 Cloudflare 官方 API 并更新本地缓存。控制台每次轮询网关状态时，即可获取最新额度数据。

## 4. 内存控制与性能调优

### Q7: 控制台提示 `标准回收模式 (启动参数可加 --expose-gc)` 是什么意思？
> **答**：代表当前 Docker 容器的启动命令中未包含 `--expose-gc` 参数。
> - 在此模式下，首包暂存释放、背压流控与连接销毁依然正常工作；
> - 若需要启用 V8 底层主动垃圾回收，可在 `docker-compose.yml` 中配置：
>   ```yaml
>   command: ["node", "--expose-gc", "server.mjs"]
>   ```
> - 重启容器后，控制台将显示 `V8 原生 GC 已就绪`。

## 5. 容器网络与系统排障

### Q8: 使用 Macvlan 模式分配独立 IP 后，局域网设备无法访问容器或连接不稳定？
> **答**：通常是因为宿主机物理网卡未开启 **混杂模式 (Promiscuous Mode)**。
>
> - **原因**：Macvlan 会为容器生成独立的虚拟 MAC 地址。默认情况下，部分物理网卡驱动会直接丢弃目标 MAC 不是宿主机本身的流量，导致局域网设备无法正常与容器通信。
> - **排查与解决步骤**：
>   1. 临时开启混杂模式：
>      ```bash
>      sudo ip link set eth0 promisc on
>      ```
>      *(将 `eth0` 替换为实际网卡名)*
>   2. 群晖 NAS 开机自动启用：在【控制面板】➔【任务计划】中新增开机触发的任务，运行命令 `ip link set eth0 promisc on`；
>   3. 虚拟机环境 (ESXi / PVE)：在虚拟交换机安全设置中，放行 **混杂模式** 与 **MAC 地址更改**。
